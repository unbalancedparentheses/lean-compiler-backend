# Independent jobs and the typed stack baseline

F02–F05 now have an executable first-path implementation and an obligation table.
The path accepts the [F01 integer/control-flow profile](SEMANTICS.md) and emits
Apple ARM64 assembly. All resulting artifacts are **uncertified**. The source,
target-helper and binding theorems below do not compose into a compilation
preservation theorem; C01/C02 remain open.

## Use the new path

The existing CLI/default backend retains its broader compatibility coverage.
The first path is opt-in and rejects memory, calls, shifts, conversions, void
results and the other exclusions in the semantic ledger.

```sh
nix develop
lake build lcb lcb-tests
.lake/build/bin/lcb --first-path examples/arithmetic.ssa -o arithmetic.s
.lake/build/bin/lcb --first-path-eval examples/arithmetic.ssa add32 4294967295 2
.lake/build/bin/lcb --write-job examples/arithmetic.ssa add32 add32.job
.lake/build/bin/lcb --replay-job add32.job -o replay.s
.lake/build/bin/lcb --write-artifact add32.job add32.artifact
.lake/build/bin/lcb --replay-artifact add32.artifact -o replay-artifact.s
.lake/build/bin/lcb --job-info add32.job
```

`--first-path-eval` compares source, MIR and typed-assembly models and prints the
result only when all return the same value. Its budgets are 100,000 source steps
and 1,000,000 steps per target model. Exhaustion is explicitly inconclusive.
Native execution is a separate test. `--first-path ... --require-proof` fails
with `certificationUnavailable`; it neither falls back nor overwrites an existing
output file. The API also refuses the `nativeBinary` evidence request.

## Frozen boundary and identities

`Verified.prepareJob` imports one function. `prepareModule` additionally rejects duplicate emitted
symbols. `compileFunction : FunctionJob → Except CompileError FunctionArtifact`
is pure and receives no module tables, filesystem access, clocks or cache.

A job contains:

- `CodeInput`: version, source/target semantic versions, target, pipeline revision,
  compiler source/build identity, symbol namespace/name/export policy, numbered
  source, exact ABI plan, exact frame layout, imports and consumed facts.
  Imports/facts must be empty for this leaf profile.
- `DebugInput`: sorted unique source records with normalized logical paths and
  source identities, and sorted structural source origins. These bind to the
  exact code artifact but do not influence selection. No DWARF or native debug
  information is emitted yet.
- Evidence request and proof profile. Only `none` can succeed. A theorem's name
  or an axiom allowlist does not itself create evidence.

`Canonical.validateSource` reifies numbered source to canonical local names,
reruns admission and compares the exact result. This rejects inconsistent IDs,
width tables, literal widths, predecessor order and malformed SSA. It remains an
unproved executable checker, so the stored source is raw `Source.Function`, not
proof-carrying `CheckedSSA`.

The compiler identity is the SHA-256 of a domain-separated manifest of compiler
source hashes and pinned build configuration. [compiler-build.json](../compiler-build.json)
and `Verified/BuildIdentity.lean` are generated by
`python3 scripts/build_identity.py --write`. CI checks they are current and compares the executable’s `--build-identity`; rebuild
after regeneration. This is a source/build-config identity, **not** an attestation
of a native executable or host environment. Proof-only and test modules are
excluded from code dependencies; the actual proof dependency profile is separate.
Old jobs with a different compiler identity are explicitly refused, even if
source syntax is otherwise supported. The pipeline revision is also checked.

`Codec.identities` returns four domain-separated canonical byte sequences;
`Codec.fingerprints` computes their SHA-256 labels:

| Identity | Exact contents |
| --- | --- |
| Code input | Frozen `CodeInput`, including signature, target, layout and compiler identity. |
| Code | Code-input bytes, typed stack MIR, typed assembly and rendered fragment. |
| Debug | Code bytes plus source/origin metadata. |
| Evidence | Code bytes, proof profile and the explicit uncertified structural-check report. |

Hash equality is never the acceptance criterion. `verifyArtifact` recompiles the
requested job and compares the complete structural artifact. Replay envelopes
are decoded by reconstructing the same baseline and comparing exact canonical
output bytes. Cache consumers must use `decodeArtifactFor expectedJob` or call
`verifyArtifact expectedJob` after decoding; replaying an envelope by itself does
not establish that it is the cache entry the caller requested. This approach
provides replay and binding, not compilation-speed savings from a persistent cache.

## Wire contract, version 1

The packet kind is a length-prefixed UTF-8 string followed by an LE64 version.
Kinds are `LCB-job` and `LCB-artifact`; dependency records use `LCB-code-input`,
`LCB-code`, `LCB-debug` and `LCB-evidence`. All currently use version 1.
Numbers and array/string/byte lengths are unsigned LE64. Booleans and constructor
tags are single bytes. Strings are strict UTF-8, at most 4096 bytes. Packets are
at most 1 MiB; source/ABI/debug collections have the profile bounds enforced
before decoding their elements. Proof profiles allow at most 64 axiom entries,
with the same limit on encoding and decoding. Bit vectors have a width tag followed by exactly
four/eight little-endian bytes. Encoders reject overflow instead of truncating.
Decoders reject unknown tags/versions, malformed UTF-8, noncanonical Boolean
bytes, oversized/truncated collections and trailing bytes.

Records use the fixed field order in `Codec.lean`, not field-name maps. The job
payload is `CodeInput`, debug input, evidence-request byte, proof profile.
`CodeInput` order is version, source semantics, target semantics, target, pipeline,
compiler revision, compiler build identity, symbol record, source, ABI, layout,
imports, facts. Layout is version, value offsets, stage offsets, frame bytes.
The source record is result width, parameter widths, value widths, blocks;
blocks contain phis, instructions, terminator. Other record fields are serialized
in declaration order in `Job.lean`/`Plans.lean`. Tags are:

| Construct | Tags, starting at zero |
| --- | --- |
| Width | word, long |
| Source operand | local, literal |
| Source operation | copy, binary, compare |
| Binary operation | add, sub, mul, and, or, xor |
| Comparison | eq, unsignedLT |
| Source terminator | return, jump, branch |
| Label | entry, body, edge |
| MIR scratch register | R0, R9, R10 |
| Slot | value, stage |
| MIR instruction | enterFrame, leaveFrame, readArg, constant, load, store, alu, compare |
| MIR terminator | jump, branch, return |
| Assembly instruction | subSP, addSP, load, store, movz, movk, alu, cmp, cset, cbnz, jump, ret |
| Assembly condition | eq, lo |
| Evidence request | none, kernelTypedAssembly, nativeBinary |
| Evidence result | uncertified (the only implemented constructor) |

Each constructor serializes its arguments in declaration order. A source phi
serializes destination, width, then predecessor/operand pairs. The artifact
packet contains four byte strings: job packet, code identity bytes, debug
identity bytes, evidence identity bytes. No arbitrary decoded machine code is
executed: products are reconstructed and compared. Job decoding additionally
re-encodes and compares for canonicality. SHA-256 is tested against known and
binary/padding-boundary vectors and independent Python `hashlib`; it is unproved.
The codec is also tested, not proved. Changes to this contract require a new
wire version; compiler implementation changes update the build identity.

This is the implemented refinement of F00's proposed schemas: raw numbered source
is honestly named instead of `checkedSSA`; ABI and layout are frozen explicitly;
artifact decoding uses a recomputation envelope; the compiler identity binds
sources/build configuration rather than an executable image. These choices do
not upgrade the evidence level.

## Typed lowering and model boundaries

`StackMIR.lower` assigns every value an eight-byte slot and reserves separate
phi staging slots. Word accesses use only four bytes. Entry stores parameter
registers; each source assignment loads R9/R10, computes and stores its result.
Each edge stages every phi source before committing any destination. Source
branches select an edge before its transfers execute. Frame entry/leave and
physical register roles are explicit; there is no allocator or optimization pass.

`TypedA64.select` lowers MIR into typed instructions, expands constants with
`movz`/`movk`, and lowers comparisons to `cmp`/`cset`. `TypedA64.render` validates
again before creating text. The validators check slot ownership/widths, staging
initialization, frame regions and phase, branch targets, allowed registers,
encodable offsets/immediates, and return/teardown structure. They do not prove
value flow: an in-bounds load from the wrong value slot can remain legal.

`Machine` supplies executable MIR and assembly transitions. W/X aliases,
little-endian owned-frame bytes, byte initialization, SP, caller-register
snapshots and NZCV are explicit. Comparison flags are defined through target
subtraction, separately from source comparison. Unbounded `Steps`, `Returns`,
`Diverges` and `HasBehavior` are separate from bounded testing. `EntryState`
describes arbitrary compatible caller states; the executable test initializer
uses known register sentinels and nonzero high word-argument bits.

This is an owned-frame target model, not the full ARM ISA or address space.
Model checks that detect bad accesses, clobbers or return stacks are assertions,
not emitted native guards. An eventual preservation proof must show they never
fail in admitted executions. Extending the frame to full memory, relating the
instruction model to the ISA, rendering, assembly, relocation and native
execution remain explicit boundaries.

## Pass obligations (F05)

| Pass/boundary | Invariant and semantic relation | Evidence now; failure behavior | Remaining composition obligation |
| --- | --- | --- | --- |
| Text/import → numbered SSA | Types, dominance/availability, exact phi predecessors; name/constant normalization preserves input meaning. | Executable admission and canonical revalidation; invalid/unsupported/resource errors. | Prove checker soundness, source progress and importer/interpreter correspondence. |
| Job → ABI/frame plans | Signature locations, disjoint typed value/staging slots, frame bound and fixed entry environment. | Exact recomputation/equality checks plus layout alignment/coverage/disjointness/encoding proofs; mismatch rejects. | Prove checker soundness and byte-access/lifetime simulation. |
| Source → stack MIR | Available values equal initialized slot bytes; staged sources refer to old environment; matching PCs. | Structural validator, model comparisons, mutation tests; failure rejects. | Operand/assignment/branch simulation, simultaneous transfer theorem and source-to-MIR composition. |
| MIR → typed assembly | Register aliases, byte memory, frame state and expansion PCs correspond; flags are scratch except in compare expansions. | Structural validator; W/X, ALU, compare-flag and frame helper proofs; failure rejects. | Constant materialization, integration of byte load/store lemmas into expansion simulation, and non-stuttering composition. |
| Typed assembly → text/binary | Text/encoding/branches/linking reflect modeled instructions and ABI. | Native C/QBE tests, maximum frame and register probes; invalid forms reject. | Renderer/ISA/assembler/linker refinement or explicit assumptions; no binary certificate. |
| Artifact acceptance | Exact requested job and baseline output, including metadata/evidence dependencies. | `verifyArtifact_binds`; full recomputation and exact equality; corruption rejects. | Baseline preservation, codec correctness and external planning correctness remain separate. |
| Evidence request | Required level is never replaced by weaker evidence. | `compile_refuses_unavailable`; all non-none requests reject. | Instantiate/audit the actual composed theorem before adding a certified result. |

There is no transformation fallback: compilation fails at a failed boundary.
A caller may explicitly choose the separate compatibility backend; that is not
a certified fallback. No cache checksum, successful test, structural validator
or binding theorem is evidence of source-to-machine semantic preservation.

## Entry-state soundness

`EntryProofs` connects the actual initializer to `EntryState`: valid signature,
arity, aligned/available frame and non-wrapping SP conditions make initialization
succeed, and every successful result satisfies the MIR entry predicate. The
assembly adapter satisfies the corresponding predicate, including its zero-frame
phase convention. Word arguments deliberately retain garbage in their upper
register bits; the proof establishes their low-width view. These are model-entry
facts, not a native loader/ABI implementation proof or a lowering certificate.
`bounded_entry_exists` gives a witness for every supported signature/frame.
`EntryExamples` instantiates it for a returning zero-frame function, a sum loop,
a cyclic phi swap and a maximum 4080-byte frame. These witnesses are checked by
Lean's kernel (including `decide +kernel`), not native evaluation. Unit tests
separately admit and execute these exact fixtures through all three models.

## Next composed-proof checkpoint (C01)

The next relation should connect each available source value to initialized bytes
in its assigned value slot. Keep the other frame bytes existential: a word store
initializes four bytes of an eight-byte slot, so requiring the whole slot to be
initialized would be stronger than the implementation. `FrameProofs` now supplies
exact written bytes, outside-span preservation, address/store correspondence,
same-width load-after-store reconstruction and preservation of disjoint loads.
The remaining step here is to establish and preserve the source-value/slot relation.

For a phi edge, freeze the predecessor environment before staging. Prove that
every staging store preserves all value slots, then that every commit reads its
staged value while preserving the other staging slots. Only after all commits
should the relation expose the destination environment. This is the point where
cycles must be handled simultaneously, rather than by sequential substitution.

The MIR/assembly relation must also account for instruction expansion and omitted
zero-byte frame operations. The assembly model starts a zero-byte frame active
and leaves it active through return, whereas MIR executes explicit enter/leave
operations. Equality of the raw `active` fields is therefore not the invariant
at every boundary. Compare the relevant phase, SP and owned memory, and use a
finite progress measure for empty expansions so that divergence cannot be
introduced or erased by an infinite sequence of administrative steps.

After operand, phi and expansion simulation, compose against arbitrary
`EntryState` callers and the unbounded behavior relations. Keep the existing
bounded evaluators as tests; a fuel limit is not a termination or divergence
proof. The first certificate must remain unavailable until checker soundness,
progress and the full return/divergence statement apply to the actual pipeline.

## Proof and qualification report

**Implemented:** pure jobs, explicit plans, typed MIR/assembly and their frame
models, versioned replay, separated identities and uncertified evidence handling.
Persistent caches, actual parallel worker scheduling, native debug information,
object files, Linux targets and register allocation remain future work.

**Proved:** the earlier source facts; actual target-helper facts for normalization,
register read/write/aliasing and non-clobber, frame enter/leave restoration,
comparison flags and all six ALU operations against source bit vectors; actual
frame-plan offsets, alignment, coverage, disjointness and encoding bounds; bounded
target return/exhaustion facts; actual store-span size preservation, outside-byte
preservation, initialization and exact little-endian byte contents, reconstruction
of word/long values and preservation of disjoint loads (including uninitialized
read failures), plus SP-relative address/store correspondence
inside a valid owned frame; exact artifact binding and unavailable-evidence
refusal. `scripts/ProofAudit.lean` prints every public theorem and `check.sh`
enforces the measured axioms. Normalization, byte-store size, slot alignment and target run facts use `propext`;
other arithmetic/target/source facts use `propext`/`Quot.sound`. Binding/refusal,
array-offset, store-initialization and load-after-store reconstruction facts
additionally use `Classical.choice`. No native-evaluation axioms or admitted goals
are accepted.
No composed preservation, admission-soundness or codec theorem is claimed.

**Tested:** unit/model/negative controls; 25 fixture functions with fresh-process
and concurrent-process replay, module-order independence and independent hashes;
32,000 arithmetic/comparison plus 8,000 loop/ABI cases per typed/baseline/QBE
backend; the 4080-byte frame, word high bits and callee-saved registers; two
fixed-seed campaigns with 24 generated cyclic-phi functions and 144 inputs
through Python, source/MIR/assembly models and native backends. Deliberate wrong
loads, saved-register clobbers and backedge corruption are detected. QBE only
promises low-word return bits: its identity function's upper bits are not treated
as a mismatch against this path's stronger zero-extension behavior.
Failures from these Python campaigns retain replayable workspaces under
`.build/first-path-failures/`. Larger campaigns can use
`python3 scripts/first_path_fuzz.py --seed SEED --require-native`.

**Pinned qualification:** `nix flake check --no-write-lock-file -L SNAPSHOT`
passed on `aarch64-darwin` on 2026-10-19 at 15:04 UTC, using a clean copy of all
tracked and untracked project sources (excluding build outputs). The tested
compiler source/build identity is:

```text
9c571508353d48fc9fcd40798ce06d2821f49d52215eac1a5f5903b843ee8521
```

The run built both executables, checked all 36 public theorem dependencies and
ran `scripts/check.sh`, including the existing integer, control-flow, memory,
blit, call, stack-argument and fuzz suites. The existing 616 original-QBE memory
overlap mismatches remain separately reported known discrepancies, not matching
cases. Linux and Intel Mac builds/native execution were not measured in this run.
Local run metadata and the full log are retained under
`.build/load-store-qualification/`; they are generated results, not certificates.

**Remaining assumptions:** Lean's kernel and audited foundational axioms for the
listed facts; adequacy of the source/target models; caller-supplied source and
metadata identity correctness; toolchain/runtime trust for executed tests; and
the native environment/stack assumptions from F00. The immediate proof work is
C01: checker/availability soundness, integration of frame lemmas into the
source-value/slot relation and simultaneous parallel-transfer lemmas,
then composed simulation with matching return/divergence and no target stuckness.
