# Exact aggregate signature aliases

Private candidate based on main 2c43795. Compiler identity: `66254fa17af51e5e7ad221eb67918b4b9779b25e307b8cb56e45977a69d9f651`. No main source edits or commits.

The validator previously required identical aggregate names across direct calls. It now accepts exact declaration structure modulo recursively equivalent prior named types. Field order, scalar width and floating class, counts, explicit alignment option, union identity and ordered variants, opaque size and opaque/defined distinction remain exact. Explicit alignment versus equivalent natural alignment remains conservatively distinct. This is not general ABI equivalence. Forward or recursive aggregate types remain refused. Recursive functions are covered.

Canonical metadata is computed after checked module layouts, once per module validation and once during interpreter initialization; individual calls reuse it. Module interpreter indirect signatures use the same matching rule. Program-only validation without module declarations remains nominal. Emitters and original aggregate declarations are unchanged.

Fresh compiler/unit builds and full unit executable passed, including direct/indirect nested interpreter checks and negative cases for FP class, opaque/union identity, alignment, count form, field order and nested class. All 147 exact proof-audit assertions passed; this is unchanged existing proof coverage, not a proof of the new compatibility rule.

All three LCB modes and unchanged original QBE passed on all five targets: 13,440 LCB checks and 4,480 original-QBE checks. Each entry includes recursive function calls with named aggregate parameters, explicit variadic marker and an unused scalar variadic tail, then aggregate returns. C checks every returned byte against a pre-call snapshot and checks a sum. No aggregate anonymous va_arg retrieval is claimed. Linux ARM executes natively in Docker, x86/RV via QEMU, Apple ARM natively and Apple x86 via Rosetta.
