# Exact aggregate signature aliases

This slice allows separately named aggregate declarations with the same exact structure to agree in direct-call signatures and indirect interpreter checks. Canonical representatives follow checked declaration order and recursively canonicalize prior nested names. Scalar class/width, field count/order, union identity/variant order, opaque size and explicit alignment options remain exact. This is deliberately narrower than general ABI equivalence: `{ l 2 }` and `{ l, l }`, or explicit versus natural alignment, still differ. Forward/cyclic aggregate types remain refused; recursive functions are supported.

Module validation builds the alias table after checked layouts, and interpreter initialization stores it for indirect calls. Individual call checks reuse this metadata. Program-only validation without declarations remains nominal. Original declarations and target ABI classification/emission remain unchanged. No preservation proof for this compatibility rule is claimed.
