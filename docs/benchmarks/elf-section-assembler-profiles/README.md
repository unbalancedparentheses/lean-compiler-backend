# ELF section-name assembler profiles

The printable-name implementation decodes IR strings, then quotes/escapes the section name in assembly. GNU assembler decodes those escapes into object-name bytes; LLVM's integrated assembler preserves the backslashes literally. Thus quote/backslash names do not have identical object bytes across assemblers. The previous Linux qualification used GNU, while Clang-based CI exposed the unqualified LLVM expectation. No compiler emission or parser change is made here.

The helper now assembles a fixed independent one-byte section containing a quote and backslash. Its exact name, type, flags and size must identify one of two known profiles; unknown behavior fails. Expected fixture names are computed from that profile, not learned from compiler output. Exact header counts, allowed section types/flags, 31 global symbols, wrong-name and wrong-value controls remain enforced.

Six [actual-main matrices](main/campaign.json), using committed retained-TLS identity `4b41bddb…`, pass all three Linux targets with GNU and LLVM assembly profiles. Each executes baseline, allocated, optimized and unchanged QBE output against C. GNU profiles use the guest toolchain. LLVM profiles use host Clang to cross-assemble and the guest GNU C driver to link; ARM executes natively in the VM and x86/RV through QEMU. These are explicit mixed-toolchain profiles, not a claim that this local runner reproduces CI's entire Clang environment. An additional [LLVM 21 object-only probe](independent-llvm21/report.json) verifies the reference metadata with CI's compiler generation.

There is a further reference-spelling boundary: LCB canonicalizes `d space`, `d\040space` and `d\x20space` into one decoded name. GNU also coalesces original QBE's raw spellings. LLVM preserves QBE's latter two spellings separately, giving **31 reference custom sections versus 29 LCB custom sections**, while all 31 program symbols and runtime values still agree. The helper records the exact reference-only names instead of treating them as LCB output or hiding extra sections. This remains a scoped metadata-compatibility difference with original QBE under LLVM.

The final runner verifies source/helper/compiler pre/post bindings and complete Linux host/guest artifact equality. Sixty-nine ELF objects/executables are omitted from this repository copy; paths/hashes remain in `omitted-binaries.json`. Earlier failures are preserved: one runner tried to stat embedded Python code as a filename, and the second correctly rejected the two newly discovered reference-only sections. An independent initial review checked only a 29-name subset and is explicitly superseded by its corrected all-header audit. No failed attempt is counted as a successful profile. The historical GNU results remain valid; their interpretation as portable canonical object names is withdrawn. [CI run 39777689834](https://github.com/unbalancedparentheses/lean-compiler-backend/actions/runs/39777689834) passed all three pinned Nix runners (Linux x86, Linux ARM and macOS) on commit `a32fc5c`; exact job results are retained in `ci.json`. This CI result qualifies that helper checkpoint, not subsequent source changes.
